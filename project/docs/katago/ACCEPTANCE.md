## 运行资源与测量边界

部署使用明确plan:free的独立Docker蓝图。公开Free规格0.1CPU/512MB、计算资源$0/月；账户最终账单、剩余额度和计费超额无法从被拒绝的后台确认。Free休眠、共享750小时、带宽和构建分钟限制见RENDER-OPTIONS.md。未购买或升级任何付费实例、数据库、Redis、磁盘或监控。

Render实际cgroup报告512MiB内存上限、CPUquota0.15（运行时观测，与公开计划表分开记录）。模型初始化1,399ms；首次健康HTTP约1.78秒，服务当时已运行，不是休眠冷启动。四个真实分析HTTP分别6.67/7.31/6.29/7.25秒，均64visits；随后容器峰值73,474,048字节，约70.07MiB。健康状态中的peak是该容器生命周期cgroup峰值，不是全工作区或账单指标。

Linux容器限制0.1CPU/512MB的最终CI：四次HTTP约5.70–6.10秒，cgroup峰值约85.86MiB。原生arm64引擎单独约53.48MiB、0.47–0.59秒。这些环境不可相互替代，也不保证下一次延迟相同。

固定真实KataGo1.18.1 / Eigen CPU、官方g170-b6c96-s175395328-d26788732，1分析线程/1搜索线程/1Eigen线程、64visits、15秒搜索上限、2项等待，黑方视角。模型老且小，少量搜索仅用于复盘参考；不是自动死活裁判、终局重判、精确人类段级位或棋力评估。

## 已发现及修正

1. 干净Docker最初未复制pnpm-workspace.yaml的既有esbuild构建许可而安装失败，现复制原许可和.npmrc，锁文件不变；后续真实Linux镜像构建/运行通过。
2. 原离线浏览器测试硬编码0.21.3缓存名，更新后测试造错缓存；改用同一APP_VERSION，仍验证未缓存首离线恢复页面。程序的离线逻辑未改。
3. 协议使用官方analysisPVLen而非未支持字段；规则警告不能静默采用转换设置。已有真实请求无规则警告，所有推荐/PV仍由共用落子内核复核。

## 知道的限制

- 只接自由双人对弈终局后复盘；不是AI对手或联机对弈中的提示器。
- 服务端重新验证提交的结束事件，但没有登录或身份认证，不能当作防作弊系统。CORS只限制浏览器来源，额外有全局资源上限。
- 当前最多1600有效事件/256KB和[-100,100]半整数贴目；不支持的原局保留，明确拒绝分析。
- 模型无法保证任意死活或最终赢家，双方确认结果保持不变；预测数值可能与已确认面积结果不同。
- 分析联网，离线本机下棋/复盘仍可用。公网API仅允许原GitHubPages Origin；本地调试需独立配置允许Origin。
- Render后台仍受权限拒绝；实际部署由用户创建，助手完成源码、配置、真实接口检查及后续前端发布。后台平台日志与费用页面没有宣称已读。
