# 成员反馈与迭代记录使用说明

当前主线 T17 0.17.0，基线 T16 0.16.0。没有预装真实成员答复、活动经历或 CAS 工时。应用默认只在当前浏览器资料中保存，不发送、不要求姓名、班级或联系方式。

## 活动结束

从任一页面页脚进入“可跳过的半分钟反馈”，或使用 `#/feedback`。先选择活动编号和日期；没有活动时可建立，编号留空会生成稳定编号。日期应由实际活动使用者确认，程序的今天默认值不是活动已发生证明。

难度、最喜欢的活动、希望下次改变什么都可留空；可以直接“跳过并返回”。关联问题/资源是可选项。成员可自行选择是否愿意将答复用于汇总导出，默认不选。不选仍保存在本机教师汇总中，审核报告排除这一份。

点击“提交这一份”后等待已保存提示，表单清空。点“下一位成员（空表）”后可再次填写；前一份原文不会出现在成员表单。重复点击同一提交只写一份。这里的提交编号识别一次填写，不识别人，也不能证明不同答复来自不同成员。

## 教师汇总

进入“教师视图 → 反馈与资源迭代”或 `#/teacher/evidence`。选择活动即可看到实际答复数、各选项计数、每项缺失和原文。分母都是当前活动答复数，不是出勤或独立成员人数。没有答复时只显示空态，不显示满意度、改进效果或成员评价。

一条记录的“删除”须再次确认；其他答复、草稿和题库保留。改进日志中引用被删答复时显示“引用已删除”，不伪造替代证据。

开发验证工具折叠显示在汇总底部，手动载入的三份答复明确为测试。成员活动列表不列出测试活动；报告默认排除测试。固定样例只检验计数，并非真实反馈。

## 从反馈建立资源改进

答复可关联“题目过难/说明不清/程序错误/其他”与精确题目版本。在教师汇总点击“关联改进条目”，填写问题、证据、拟改资源、修改内容、日期、验证方法和下一步。

“在 T14 建立修改前后版本”会保留两个版本：正式题先复制为新的 LOCAL 资源 r1，再建 r2；已有本机草稿则在同 ID 递增 revision。本操作向题干补充填写的文字，更多棋形、提示和答案修改继续在 T14 编辑。新稿不继承原验证、不自动发布；正式题和冻结内容不被覆盖。

日志和草稿一起保存，失败整笔回滚。打开 T14 修改稿前会说明将替换当前未提交的编辑会话，已保存版本不受影响。草稿损坏时先从备份恢复，不能用空库覆盖。

“已修改草稿”与“已实施”分开。真实实施日期和实施后观察必须手动填写；没有后续反馈则留空，显示未观察。程序不会判定改进有效。正式内容需后续主线审查和重新冻结，T17 本身只建立本机副本。

## CAS 过程

选择活动后在 CAS 过程页记录本人设计/修改、同伴贡献、AI 协助、参考资料、真实实施和自行反思。可以手填实际分钟，也可以留空；不是自动认定的 CAS 工时。四个反思提问和下载模板是空白提示，程序不代写已发生经历。

## 分享前审核与导出

在“审核与导出”生成预览，检查并删减活动简名、成员原文、改进和过程自由文本中的个人资料。删减只改变本次报告副本，原记录保留。若要移除原文，回汇总逐条删除。题目全文版本快照不放入分享报告，仅保留版本引用。

下载 Markdown 或结构化 JSON；“打开报告 / 另存 PDF”打开安全 A4 报告页，再由本机浏览器打印或另存 PDF。弹窗被阻止时允许本页弹窗，或下载 Markdown。导出不会自动发送给学校或其他人。

完整备份在“准备离线与备份”，包含未删减原文与前后题目快照，是恢复用途，不是审核后的分享报告。可独立清除“活动反馈、改进与 CAS 过程记录”；清进度或清反馈不删除正式题库和教师草稿。

## 离线与故障

首次在线或本地服务加载后，先看到“已可离线”。0.17.0 的 8 项必要资源含正式题库和 CAS 空白模板。网络关闭后反馈与本机保存可用；直接双击 file:// 不承诺同等离线能力。

保存失败会保留当前填写内容；先备份原数据，再处理浏览器限制或空间不足。损坏记录停止保存并提供恢复入口，不用空数据覆盖。应用更新由使用者触发，先保存正在填写的内容；尚未提交的表单不是已保存记录。

本次仅完成程序及开发测试；真实成员使用、学校 CAS 认可和实体打印仍未发生或未测。
