# 启动与部署

## 最简单的本机/局域网运行

解压app.zip，保留dist与dist-server的相对位置。使用Node22.22.2+（22系）、24.15+（24系）或26+，从解压目录运行：

```sh
node dist-server/server.mjs
```

macOS也可双击“启动联机对弈.command”；启动器不安装软件、不使用付费服务。终端保持运行，Ctrl+C结束服务。默认端口4190、监听0.0.0.0，允许其他设备访问此服务；若只供本机测试，先设置HOST=127.0.0.1。端口占用请关闭自己之前的服务或设置PORT=另一未占用端口，不要结束不认识的程序。

服务只提供dist中的应用文件和房间接口，不对外列出项目源文件或私人数据文件。Node服务是必需的；仅用Python静态服务可以打开离线教学，但不能建立联机房间。app包的服务已经打包，不需要node_modules。源码版使用锁文件安装后执行pnpm build、pnpm start；开发后端可pnpm dev:online，前端改动需重新构建。

启动终端显示localhost和网卡候选地址。同一Wi-Fi上的双方应使用同一个局域网地址；如系统询问接收连接，只允许可信网络。候选地址不是已验证的公网地址；访客网络设备隔离、防火墙或移动网络会影响连接。

## 自有服务器部署

服务器必须支持持续运行的Node进程、同源WebSocket升级和持久文件目录，运行单个实例。将dist/与dist-server/放到同一应用目录。HTTPS反向代理应保留Host、Origin并把/api/online/ws升级转发到同一个Node进程，同时代理其静态资源。设置PUBLIC_ORIGIN为实际网站源（例如https://go.example.org，替换为自己的真实地址），HOST=127.0.0.1、PORT为代理上游端口，GO_CLUB_DATA_FILE指向服务器不公开的持久目录/rooms.json。仅环境变量中指定源，不把密码写进源码或交付包。

反向代理、域名、TLS证书及跨地点实机访问在本次环境未部署/未测。本包不适合无持久进程的纯静态托管。多副本、无状态函数、共享写一个JSON文件都会破坏单一房间事实源，暂不支持。若开放到公网，管理员还需在入口设置连接和请求限流、访问日志保留策略与可用性监控；内建小规模容量不能替代托管平台的抗滥用措施。

## 配置

| 项目 | 默认/含义 |
|---|---|
| HOST | 0.0.0.0；明确联网监听，可设127.0.0.1限制本机 |
| PORT | 4190，整数1–65535 |
| PUBLIC_ORIGIN | 未设置；部署后填准确https网站源，校验浏览器Origin并生成邀请网址 |
| GO_CLUB_DATA_FILE | 应用目录runtime-data/rooms.json；含棋局、可选昵称及凭据散列，勿发布 |

/api/online/health返回服务就绪、版本和规则；不返回房间列表。客户端WebSocket由当前网站地址生成，HTTPS用wss。不要配置外部CDN作为核心依赖。

## 更新、备份和故障恢复

1. 让双方先导出仍在进行的棋局，停止房间服务，复制runtime-data/rooms.json到不公开的备份目录。停止后再复制可避免读到更新中的文件。
2. 替换应用资源，保留私有数据路径及原网站来源，重新启动。前端如提示新版本，应先保存本机工作再应用；不会在编辑/对弈中强制刷新。
3. 双方用原会话刷新恢复。服务从合法setup与动作重放盘面、提子、重复历史和结果，恢复凭据散列及确认清单；断线不产生胜负。
4. 私有数据损坏或未知版本会拒绝启动并保留原文件。先复制损坏文件供检查，再停止服务、恢复已知可用备份并重启；不要用空文件盖掉原记录。若本页检测服务器版本倒退，会保留本页棋局供导出。
5. 写入失败时本次操作不提交，恢复磁盘空间/权限后重试。连接不可用可导出本页最后已验证局面，或回同屏对弈。私有JSON不是公开内容导入格式，不能导入T15代替房间恢复。

同一房间最多2000个引擎事件、服务最多100个房间；双方离线超过24小时的旧房间会在下一次创建房间时清理。它是服务留存上限，不是棋局倒计时；旧局请提前导出。暂不提供密码账号、邀请权限分层、跨设备自动恢复、多实例扩展、公开观战或在线聊天。
